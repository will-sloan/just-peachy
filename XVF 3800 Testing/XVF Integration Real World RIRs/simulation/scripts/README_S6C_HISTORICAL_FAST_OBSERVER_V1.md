# Historical fast observer utilities

`s6c_historical_fast_observer_v1.py` implements the shared source-bound utilities used by three small explicit entry points. It has no direct CLI. Use one of the maintained variant READMEs below. Inputs are held original Python sources and an explicitly SHA-bound original prepared manifest; outputs are source-check receipts, new observer-bound manifests, and eventual original native receipts plus a separate scanner timing report. No model is loaded by checks or metadata-only preparation.

The original directory families are retained, but every new namespace must end `_fast_v1`. Previous source, READMEs, plans and outputs are read only. Plans retain exact original job objects and actual S6B execution epoch; the continuous composition remains S6C epoch2. Native APP/assets/profile/input hashes, gain, source extent and worker function are unchanged. Execution still uses the original full dependency verification before the original worker.

The new scan uses `os.scandir` directory traversal and one explicit fresh `os.stat` for each nondirectory entry; there is no cross-call cache. File sizes from cached directory enumeration are never used: a tiny Windows fixture found a changed hardlink retaining its old directory-entry size (46 enumerated bytes versus58 fresh-stat bytes). The initial draft and diagnosis are preserved. The old reviewed f725 scanner is a source-bound design precedent with this newly observed limitation; its bytes remain untouched. It counts regular files, hardlinks per entry, and target size for file symlinks. Dangling links and nonregular entries contribute zero, inner directory symlinks are skipped, and an explicitly selected root directory symlink can be traversed. Unsupported non-symlink reparse entries are rejected. Permission, traversal and entry errors fail closed instead of inheriting pathlib's error suppression. This is an explicit stricter observer policy; ordinary stable-tree byte parity does not prove arbitrary junction/reparse parity. Concurrent scans are not atomic filesystem snapshots. No present full storage scan is performed by the checks.

All original disk floors (C50/G75GiB), new-output cap120GiB, reservation headroom, admission/between-cell/terminal scan call sites and timeouts remain. The periodic20-second timer restarts after each completed full scan, preventing an expensive scan from immediately triggering the next one. Historical paced outer RAM increases from4 to12GiB prospectively; continuous remains12GiB. Internal historical model/thread/state limits are unchanged. The original paced observer performs a global walk at admission, before/after cells and periodic heartbeat opportunities at least20 seconds after the previous full scan completes; the long observer retains its original call sites. Scan time can delay observed sampling. The historical1.87-second benchmark is not a current estimate: the separately bound pre-paced reviewed scanner measurement was13.071137seconds for roughly187k files. This adapter requires its own source-bound benchmark; the previous scanner duration is not its timing. Root authorized one new current all-three-root benchmark after synthetic and bounded closed-subtree parity pass.

The original functions are AST-compiled into a separate dictionary with metadata constants and `__file__` pointing at the explicit new entry. No original module object is patched. The coordinator `run` AST changes only its one `lastbeat=elapsed` assignment to `lastbeat=time.monotonic()-t0`, under root authorization. The original native worker source remains exact. For B36-long, the NEW controls entry exports the scanner; an isolated proxy uses that explicit scanner while other original controls operations retain their source. The new meter stores only aggregate call/time/error fields per root; it writes `observer_invocations/<id>/SCANNER_OUTCOME.json` after the original run returns or raises. The report includes the exact PID, finite creation time and argv captured before run, explicit wrapper binding and entry name, so later inventory can bind it to the original invocation. This report is not a native completion or quiet-release receipt. Original child/invocation records and actual PID+creation closure remain necessary.

Historical paced launch and cleanup behavior is inherited, including the preexisting successful-Popen/creation-query gap; this optimization makes no new ownership guarantee. The continuous B36 wrapper retains its reviewed immediate-spawn record, shared25-second cleanup deadline, original30-second lane drain and65-second final join, and unknown-owner lease retention. Current-source summaries and later inventory/analysis require explicit admission of these new schemas/entry points before actual use.

## Commands

PowerShell and Anaconda Prompt/CMD commands for every entry are in `README_S6C_PACED_CONTROLS_FAST_V1.md`, `README_S6C_PACED_B36_FAST_V1.md`, and `README_S6C_LONG_B36_FAST_V1.md`. Use the exact EDGE interpreter path there. Checks use temporary synthetic files and metadata; prepare creates a fresh plan only. `run` requires a separately authorized exact quiet-admission document. The B36-long `worker` action is internal to the original coordinator and must not be launched manually. Root owns all actual run authorization.

## Validation and outputs

Checks cover current-file growth/shrink/deletion, regular and hardlink counts, optional real links with unavailable status if Windows privileges prevent them, synthetic dangling/file/directory links, permission/reparse failure, metered failure propagation, isolated module state, the exact single-assignment AST delta and original call names and all unchanged limits. Optional original manifest arguments exercise reviewed V4/V5 metadata admission, exact-job projection and re-bound profile/input/driver/RAM/timeout/source mutations. They do not hash PCM/model payloads or create a prepared namespace. No worker/model/native run is a fixture.

## Shared exact scanner API

Other separately source-bound observer wrappers may import this module without importing native code. `scan_details(root, regular_files_only=False)` returns current `bytes`, `files`, and visited `directories`; `tree_bytes(root)` returns the same byte count for the common os.walk-style policy. In that policy dangling links fail and non-directory nonregular stat sizes are retained. `strict_bytes(root)` selects `regular_files_only=True` for the historical rglob/is_file policy: nonregular and dangling entries contribute zero. Both modes use explicit fresh os.stat for nondirectory entry sizes and reject unsupported non-symlink reparse traversal. The original f725 helper is never changed or installed by this module.

A current-tree benchmark, if specifically authorized, must use one scan per root and bind this source and the returned counts with actual wall/CPU time. It must not substitute a previous benchmark or repeat the slow original whole tree. A bounded closed subtree may be checked against the original separately. Scanner failure is an explicit failed observation; no approximate size is returned.
