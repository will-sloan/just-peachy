# Native confirmation protocol V2

Purpose: a distinct protocol epoch for prospective176 native confirmations,8 owned Tk probes and2 full host sessions. The original pilot wrapper and every app/helper/result remain immutable. This code invokes the exact existing helper `run_one` in the same process, adds full-source completion evidence, explicit CPU affinity and Tk closure validation, then publishes the supervisor completion artifact. It never treats helper COMPLETE alone as full-input success.

Inputs: exact helper/manifest paths and SHA256 values plus literal native job ID; supervisor-provided run/job/child/heartbeat/completion/STOP environment; fresh job/protocol paths; manifest `protocol_sources={runner:binding,evidence:binding}` and equal `evidence_helper`; declared positive source/identity frames, PCM SHA, fixed source WAV and affinity `[12,13,14,15]`. The shared runner import is explicitly pinned to accepted census V4 at this campaign's immutable absolute report path, SHA `fdffb4ca…`. The evidence module is pinned to unchanged accepted `bb1b5ff8…`. Manifests and the final queue must bind these exact paths/bytes. Importing the wrapper loads only standard-library/psutil runner definitions, no models, GUI or census worker.

Before native initialization it verifies code bindings, sets and reads back the four admitted CPUs, fixes inner library pools to1, and validates the actual mono PCM source against the predeclared frame/hash. Native constructors retain their existing once-per-initialization8 model hash checks. No repeated large model hashing occurs in health. After the helper closes, accepted evidence `audit` verifies actual source, both full PCM journals, source/ASR/speaker cursors, tail/full dispatch, scheduler/worker/consumer/finalizer closure. The result is preserved as `FULL_SOURCE_AUDIT.json`; rejected evidence cannot produce protocol COMPLETE. An old inner RESULT can remain COMPLETE while the new authoritative protocol failure correctly rejects an incomplete prefix.

For `job.views`, it also checks the bound `OWNED_RESOURCE_CLOSURE.json`, exact view inventory/count/order/drain, recomputed native causal input digest, per-view widget text hashes and actual triggering event/session/clock bindings. No-text output retains no invented render activity and remains a correctness outcome for later scoring. Actual Tk command/callback proof remains distinct from headless consumer timing and physical scanout. No acoustic or lexical correctness is inferred from pipeline completion.

Outputs: normal protocol heartbeat, exclusive `FULL_SOURCE_AUDIT.json`, and either supervisor completion or `WRAPPER_FAILURE.json`. Completion includes `full_source_evidence_validated`, `completion_audit`, `affinity_verified`, `tk_view_evidence_validated` and exact source/result bindings. The root queue must require observer closed, empty observer errors, no STOP, same-process execution and full-source evidence, plus Tk evidence for GUI jobs. A fresh temporary completion file is fully flushed before atomic rename, with synchronous same-owner STOP/source checks immediately before each bounded sharing retry. Persistent failure retains evidence and does not publish completion. Post-helper native results are never rewritten.

This file alone does not authorize launch. Root independently admits the exact queue, campaign deadline/reserve, C>=50/G>=75GiB, global40GiB cap, serial execution and process ownership/exit. The wrapper spawns no subprocesses and never kills unrelated processes; cancellation uses the existing checked engine.stop callback and the supervisor's finite owned-process policy.
