# Composite native176 closed-input builder and scorer adapter

These additive helpers combine the original 171 declared completions with five fresh recovery executions. They preserve the original blocked176 checkpoint and the stopped fourth C105 result. That stopped result receives no scientific credit. No old manifest, result, scorer4260 or builder e379 is edited.

`s6d_native176_scoring_inputs_v2.py` imports the hash-pinned original builder for its one-read file/PCM cache, exact static176 declarations, unchanged V4 completion API, bb1b source/dispatch guard, original reference guard, process-absence checks and gallery selection. New code verifies the exact composite236839 and recovery freezeadae, separates historical REPORT_BLOCKED ownership closure from actual fresh FINISH5 closure, and joins each original scientific ID to its actual execution ID and immutable native manifest. Original171 and recovery5 both undergo full source WAV/PCM, paired journals, actual event dispatch, finalizer/consumer/observer, result/owner, reference and gallery checks. All176 remain required; there is no silent unavailable fallback.

The original supervisor launch stores `creation_utc` rather than numeric `creation_time`. The new parser converts its explicit timezone to Unix time and rejects conflicting forms; the result still must match the immutable CLOSED_LOCK identity. The stopped child's launch/STOP identity is preserved and checked for fresh absence too. Access errors never mean absence. The original stale census failure remains recorded; new5 requires the unchanged successful FINISH/census/keep-awake closure. Neither historical state nor its action is rewritten.

`s6d_native_correctness_composite_v2.py` copies scorer4260 with only a declaration-selection adapter. Original two88-job manifests and recovery manifests overlap five scientific IDs, so the old index rejected them. The adapter requires exact root/builder-bound `execution_selection` for all176 IDs, selects171 original plus5 recovery manifests, and rejects duplicate, missing or foreign alternatives. All text/name/timing/reference functions and the downstream scoring loop remain unchanged. It does not project or relabel old manifests. Actual interruption and changed scheduling conditions stay part of interpretation; this remains headless evidence, not GUI render or scanout.

## Inputs and outputs

Run maintained `SIM/scripts` paths. Copied freeze files are review evidence; the scorer's existing dependency paths expect the original repository layout.

`prepare --output FRESH_R_DIRECTORY` reads pinned static source/metadata, original blocked checkpoint and stopped-result metadata, and creates only an unapproved `PROPOSAL.json`. It does not audit the171 completed source/journal outputs, query live processes, run models, score text or create root approval.

The future `build --admission ROOT_JSON --sha256 SHA` input must have:

- schema `s6d-native176-scoring-build-admission.v2`, status `ROOT_ACCEPTED_NATIVE176_COMPOSITE_CLOSED_INPUT_BUILDER_V2`, exact owner thread, and `allow_closed_input_construction=true`.
- Exact `{path,bytes,sha256}` bindings for `builder`, `readme`, `proposal` and `composite`.
- `recovery` with actual `approval`, `root_admission`, `supervisor_launch`, FINISH `checkpoint`, `closed_lock` and `supervisor_closure` bindings. Actual queue admission status is `ROOT_ADMITTED_NATIVE176_RECOVERY5_PENDING_SUPERVISOR_PREFLIGHT`; its `composite_map`, queue, original authorities, freeze and approval must match.
- Fresh `output_root` under this study's G payload root and fresh nested `score_output_root`.

Before publishing, both state locks must be absent, all original/supervisor/stopped/recovery PID+creation instances must be freshly absent, and C50/G75 floors must hold. No process is stopped. Successful build writes exact gallery rows, `VALIDATION.json`, `SCORING_INPUTS.json` and `SCORER_COMMAND_PROPOSED.json`. It never executes the scorer. Root separately reviews the command and exact source/spec hash. A source/owner/PCM/closure error blocks input construction.

The scoring spec retains the original prospective job and comparison orders. Its `execution_selection` follows original execution order and joins by scientific ID. All four immutable manifests remain listed; selection points to the actual source of each accepted result. The fixed scorer dependencies, evaluator gallery map, complete/incomplete reference denominators, raw-output equivalence gate and censored timing populations remain intact.
