# Working per-candidate disposition proposal

This reporting helper produces a careful working proposal for all240 registered labels:44 historical B controls and196 C candidates. It does not select a winner, prune a family, add configurations, change settings, close the campaign or approve operating retention. Every final status remains pending. The original160-row registration CSV is copied byte-for-byte, and each original row including its complete settings string/digest and historical disposition is preserved in the expanded CSV. The80 later C117–C196 labels retain exact final V7 profile-route hashes and registry provenance.

Inputs are the pinned final V7 registry, original registration CSV, candidate_support/working_v2 receipt and its two exact outputs, an explicitly added completed full N03 core/coverage source, nine named closed native-batch metadata chains, and the listed completed mechanism/interpretation/review documents. No recursive discovery of scores or live native outputs occurs. Every parsed buffer is verified against its declared binding where present, then hashed exactly once per read. Sources are restricted to32MiB each. Registry parent and native job/audio/model/event payloads remain transitively bound; their heavy payloads are not reopened by this collector.

Native scope comes independently from pinned completion review, exact outer closure/admission, original manifest-binding equality and successful completed result rows. It records exact candidate/case/route membership per closed batch, including reused references. These are logical coverage counts, not additive physical inference counts. Every physical-count cell is blank. Candidate scoring coverage never grants native6 credit, even when compatible shared evidence exists. Missing native scope remains PENDING_OR_UNVERIFIED, not proven unexecuted. C083/C084 aliases receive no propagated score/native authority. C143/C146 remain distinct intended-roster conditions despite shared30s gallery content. Equal observed metrics never merge distinct settings.

The proposal retains N00 admission/support confounds, all null/nominal seeds, panel-only scopes, inactive branch/opportunity limits, conditional enrollment/calibration/scene-roster selection, source-duration differences, and pending full/paced/continuous conclusions. It is a snapshot; later results need a separate explicit version, not retroactive editing.

Outputs in a fresh `reports/S6C/20260910T123540Z/candidate_disposition/working_v1`:

- `CANDIDATE_DISPOSITION_PROPOSAL.csv`: all240 per-ID rows, original provenance, scoring/native scopes, proposed disposition, gaps and source references.
- `WORKING_DISPOSITION.md`: self-contained scope guide, source catalog and per-ID proposal.
- `ORIGINAL_REGISTRATION_SNAPSHOT.csv`: exact original bytes.
- `REGISTERED_ROUTE_SETTINGS_PROVENANCE.json`:388 current C route hashes and the two explicitly verified alias groups.
- `SCORING_AND_NATIVE_AUTHORITIES.json`: separately preserved score and closed native metadata authorities.
- `RECEIPT.json`: exact source/output bindings, counts and pure guard results; it explicitly denies final completion.
