2. PROJECT SUMMARY
------------------

Just-peachy is a local speech-pipeline and dataset-validation project. Its
current capabilities include:

* Dataset-aware speech evaluation.
* Audio loading, resampling, and channel handling.
* Voice activity detection (VAD).
* VAD-driven segmentation.
* Automatic speech recognition (ASR).
* Optional diarization.
* Speaker embeddings.
* Enrolled-speaker matching.
* Realtime microphone or prerecorded-realtime simulation.
* Speaker enrollment.
* Component performance sweeps.
* Metrics, reports, plots, and run artifacts.

The largest active application is located at:

  Software Validation from Datasets\Evaluation Tool

The Evaluation Tool supports normalized metadata and evaluation workflows for:

* AMI
* CHiME-6
* CMU Arctic
* HiFiTTS
* LibriSpeech
* VOiCES

The current realtime work is focused on OpenAI Whisper transcription combined
with SpeechBrain ECAPA speaker embeddings and cosine-threshold matching against
an enrollment database.

4. PIPELINE ARCHITECTURE
------------------------

The main PipelineRunner resolves components from YAML and processes an
EvaluationRecord through approximately this flow:

  input record
    -> audio loading/resampling
    -> VAD (optional)
    -> segmentation (optional)
    -> diarization (optional)
    -> ASR
    -> speaker embedding (optional)
    -> enrolled-speaker matching (optional)
    -> transcript assembly and diagnostics
    -> predictions, metrics, and reports

The project intentionally uses explicit component interfaces and data contracts.
Important identities such as recording_id and utt_id should be preserved through
the pipeline.

Configuration can reference reusable component YAML files. Component loading is
lazy so configuration resolution does not automatically import or load every
machine-learning model.

8. WINDOWS COMPATIBILITY FIXES ALREADY MADE
-------------------------------------------

Several Windows-specific failures were found and fixed.

8.1 Python resource module

The standard-library resource module is Unix-only. The speaker-embedding base
module previously imported it unconditionally and failed on Windows.

The import is now optional. process_memory_mb() returns None when resource is
unavailable. Memory reporting is optional, so this is safe.

Relevant file:

  app\inference_pipeline\speaker_embedding\base.py

8.2 SpeechBrain symlink privileges

SpeechBrain originally attempted to create symlinks from the Hugging Face cache
into the project model cache. Standard Windows sessions raised WinError 1314.

The adapter now passes:

  local_strategy=LocalStrategy.COPY

This avoids requiring Administrator privileges or Windows Developer Mode.

Relevant file:

  app\inference_pipeline\speaker_embedding\speechbrain_adapter.py

The model bootstrap helper uses the same copy strategy.

8.3 FFmpeg

OpenAI Whisper receives WAV paths and uses FFmpeg to decode them. If ffmpeg.exe
is absent from PATH, Whisper raises WinError 2.

The installer can check or install FFmpeg through WinGet:

  .\install.ps1 -Profile inference -InstallFFmpeg

8.4 PowerShell quoting

PowerShell/native-command quoting stripped nested double quotes from an earlier
python -c command. Prefer Python script files. If python -c is necessary, use
outer double quotes with inner single-quoted Python strings.


9. INSTALLATION SYSTEM
----------------------

A Windows-first installer and dependency profiles were recently added.

Main installer:

  install.ps1

Profiles:

  core       Dataset, audio, metrics, and reporting packages
  inference  Core plus PyTorch, OpenAI Whisper, SpeechBrain, Silero, sounddevice
  full       Inference plus Faster-Whisper and pyannote.audio packages
  dev        Inference plus pytest, coverage, Ruff, and mypy

Recommended installation:

  Set-ExecutionPolicy -Scope Process Bypass
  .\install.ps1 -Profile inference -InstallFFmpeg -DownloadModels

Installer behavior:

* Accepts Python 3.10 through Python 3.12.
* Prefers the Python 3.12 py launcher when creating a new environment.
* Reuses a functional .venv.
* Backs up a broken .venv instead of deleting it.
* Installs the selected dependency profile.
* Optionally installs FFmpeg with WinGet.
* Optionally downloads Whisper, SpeechBrain ECAPA, and Silero assets.
* Runs installation verification.
* Writes transcripts under .install-logs.

The installer has been statically validated but has not been run end-to-end in
this Codex session because doing so would replace the current broken launcher,
install packages, and potentially download large assets.

13. COMPONENT SWEEP
-------------------

The sweep runner is:

  scripts\run_realtime_component_sweep.py

The default matrix is:

  configs\sweeps\realtime_component_matrix.yaml

It builds a configurable Cartesian product over dimensions such as:

* Input recordings
* Whisper model
* CPU or CUDA profile
* Window and hop settings
* VAD profile
* Speaker threshold
* Centroid or exemplar scoring
* Word timestamps
* Beam size
* Queue behavior

The default enabled matrix produces 48 cases. Larger models and CUDA are listed
but disabled by default.

Preview without running models:

  python scripts/run_realtime_component_sweep.py --run-id preview --dry-run

Run two base cases:

  python scripts/run_realtime_component_sweep.py `
    --run-id base_smoke `
    --models base `
    --max-cases 2

Run the enabled matrix:

  python scripts/run_realtime_component_sweep.py --run-id full_matrix

Resume:

  python scripts/run_realtime_component_sweep.py --run-id full_matrix --resume

The sweep writes:

* A manifest
* Generated configuration per case
* Console log per case
* Original realtime summary per case
* Checkpointed results.jsonl
* Consolidated results.csv

Recorded performance fields include:

* Wall-clock time
* Prediction count
* Dropped-window count
* Mean and maximum latency
* ASR realtime factor
* Mean total pipeline runtime
* Mean ASR-stage runtime
* Mean speaker-stage runtime
* Speaker acceptance and unknown counts
* Mean speaker score
* Error and output paths

The current sweep measures runtime and matching behavior. It does not yet
automatically calculate transcription WER for the realtime test WAV unless
reference text is separately integrated.

15. KNOWN LIMITATIONS AND INCOMPLETE WORK
-----------------------------------------

* Faster-Whisper is registered and installable, but its execution adapter still
  raises an intentional "not wired" error.

* Pyannote is optional, potentially gated, and not part of the validated default
  realtime path.

* The main realtime matching config explicitly uses CPU. CUDA availability
  alone does not cause Whisper to use the GPU.

* Large Whisper models may exceed available memory or be impractically slow on
  CPU. Downloads are intentionally opt-in.

* runtime.max_batch_size and runtime.num_threads are currently mostly
  configuration/reporting fields and are not comprehensive model-execution
  controls.

* First-use model loading can distort realtime latency and fill the inference
  queue.

* Speaker threshold 0.70 is not fully calibrated. A proper calibration set must
  include multiple speakers, impostor trials, noise, silence, and varied
  microphones.

* With one enrolled speaker, min_margin does not provide useful ambiguity
  rejection.

* The dependency profiles use direct package names rather than a fully pinned
  lock file. A clean-machine install should be validated before declaring the
  setup reproducible.

* Full pytest was not run after all recent changes because the local .venv
  launcher was broken in the Codex shell. Python compilation, PowerShell
  parsing, requirements-reference checks, configuration resolution, registry
  checks, sweep manifest generation, and focused assertions were run.
