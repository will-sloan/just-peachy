# Private application cell and render observation integration

Purpose: connect the unchanged common Controller/Tk application to the qualified
N4 research roster, source clock, compact viewport history, shutdown validator
and process-tree resource observer. The existing numerical workers and frozen
application source remain unchanged. There is no standalone neural-launch CLI.

`ApplicationCell` in paced_application_cell.py is an internal one-cell primitive.
Construction refuses the user's input desktop before creating any Tk window.
Inputs are a fresh private output directory, the exact eight-field audio-only
job, catalog-derived backend/mode contract, frozen source path, model root, both
bound runtime manifests and the prepared research-gallery binding. The campaign
launcher must verify the source/model/configuration hashes and reviewed shortlist,
admit the exact panel job and acquire the sole model/resource slot first.

Preparation builds a fresh private Controller data directory, copies the exact
runtime metadata, selects the backend through the actual command queue, installs
the fixed compatible gallery, selects Balanced/the admitted mode/tap, disables
adaptation, and joins the V3 clock and V2 viewport ledger. The GUI is exactly
480x800 with its existing 184-pixel active pane and auto-start disabled. The
personal data root and original application checkout are not used.

The primitive's `run_source(admission_check=...)` branch is implemented for the
future reviewed launcher but **has not been executed or qualified by this probe**.
It calls the actual Controller.start_file, retains engine/consumer owners, pumps
Tk through source completion and final-label settling, then preserves the final
snapshot. The launcher-supplied check must reject changed admission/resource
ownership, disk floors and deadlines before start and perform a cheap check at
most once per second thereafter; do not rehash model payloads in that hot path.
It must never approve a candidate alongside ASR/D1 or another neural/resource run.
Always call close in a finally block, including startup/command failures. Close
drains the Controller, validates source/worker/archive closure through V2,
cancels observers, restores owned hooks, closes Tk and seals resource evidence.
Failures and incomplete starts remain explicit. CELL_CLOSED_REQUIRES_REVIEW is
not N4 acceptance, a latency pass, a memory tier, or a completed shortlist panel.

`PacedViewport` attaches after each original `_render_rows` call and on a bounded
100-ms Tk timer. It does not call the stateful label function or render again.
It records the last actually rendered rows, including finality changes without
text rewrites, and observes later scrolling/layout changes. If poll has changed
strict-filter context before a smoothed render, the timer defers instead of
combining new settings with old widgets. Original render exceptions propagate;
observer failures preserve the prefix and invalidate its evidence. It restores
only its own render hook and cancels its timer before destruction. All widget
access, log writes and final closure remain on the original Tk thread.

Outputs per private cell: PREPARED.json, optional FINAL_SNAPSHOT.json and source/
engine/archive closure receipts, viewport/SUMMARY.json plus bounded observations,
resources/RESULT.json plus bounded process samples, native Controller artifacts,
and RESULT.json with explicit scope/errors. Full transcripts, rosters and all
private evidence stay outside Git. Neither periodic point observations nor a
source-origin field establishes continuous visibility or physical scanout.

## Model-free private qualification

The probe runs eight tests on a separate Windows desktop without switching to
it or injecting input. Seven test the actual render hook, finality without a
rewrite, scroll observations, pending strict changes, clock failures, hook
ownership, original errors and thread confinement. The eighth prepares and
closes real Controller/Tk instances for the three engine families using no model
payload, with model/enrollment acquisition forbidden. No source starts. Fixture
source origins are explicitly fixtures. Actual source execution, main-bank
shortlisting, repeated paced cases, 20-minute continuity, content/naming and
whole-stack resource acceptance remain outstanding.

The launcher uses CPU14/BelowNormal, one math thread/GPU visibility off, verifies
the frozen source, preserves prior attempts, checks the campaign allowance with
6 GiB reserved and drive floors, and observes the packaging cutoff. It may run
as the admitted lightweight helper beside CPU4 extraction. This permission does
not extend to the primitive's real source branch or controlled resource testing.
