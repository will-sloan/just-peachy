# Independent same-Controller pair receipt composition

Purpose: connect the previously qualified released-source trace, engine/archive
closure and complete native journal readers across both restart sessions. This
parent-side reader preserves the full planned saved-audio job. It independently
reconstructs each leaf result and rejects disagreement with child receipts.

`restart_pair_evidence.review_pair(application, payload=..., application_owner=...,
checkpoint=...)` takes a fixed private `application` directory, the reconstructed
13-field restart execution payload, the exact exited PID/creation identity, and
an optional resource/deadline checkpoint. It returns a JSON-compatible evidence
join with all file bindings, two session summaries, raw-trace/native reviews and
explicitly unavailable acceptance scopes. It launches no process, GUI or model,
reads no audio samples, writes no production evidence and connects to no Pi.

The caller must first reconstruct the accepted selected restart plan and validate
the supervised transport, permit, private-desktop lifetime, exact script and CPU
placement. This module checks current exit of the supplied identity but cannot
establish that transport provenance by itself. Later complete-panel, viewport
row attribution, resource-sample and timing/quality reviews remain required.
`PASS_COMPLETE_RESTART_PAIR_EVIDENCE_JOINS_ONLY` grants none of those acceptances.

The reader requires fixed session paths 01/02 and unchanged source-code bindings;
bounded raw traces; the public stop at or after its planned threshold; actual
prefix/full delivery counts; matching engine, archive and native terminal
receipts; common source origins; exact publication/consumer populations; and
delivery/native completion before each release. It checks fresh native sessions,
consecutive epochs, zero source offsets, the same recorded Controller/UI/worker/
model ownership, and a second source origin strictly after the first release.
These are joins of recorded ownership observations, not a new independent object
identity instrument. Viewport scopes keep old caption history explicitly separate
from the current session; row contents are not scored here. Files are checked
again after reading, with duplicate/nonfinite JSON and reparse-path rejection.

The reader's complete dependency manifest belongs to the parent. The immutable
child still has all 122 qualified records and its unchanged 128-record limit.
Do not substitute the larger parent manifest into a child permit, drop dependency
records, change a running plan or edit earlier qualified implementations.

## Development probe inputs and outputs

`probe_restart_pair_evidence.py` consumes the two existing child/native
qualifications and their exited-owner evidence. It runs 18 tests: valid partial/
full joins, cross-file/session corruption, count/epoch/origin/order mismatches,
false acceptance, incomplete leaf reviews, changed trace files, duplicate JSON,
fixed-path dispatch and the separate parent/child manifests. Synthetic metadata
is used throughout. The three already qualified delivery, engine/archive and
native leaf readers are mocked in the file-composition fixture; they are not
claimed to be requalified by these tests. There is no new actual restart evidence.

Outputs in a fresh private directory are PROBE_OWNER, ADMISSION, source snapshots,
tests.txt, preserved synthetic fixtures, and RESULT or FAILED. Failed attempts
remain untouched. The probe pins CPU14 below normal priority, one math thread and
GPU off; uses the writer lock, fresh D1 identity/heartbeat and disk/shared-budget
guards; and permits 720 seconds and at most 8 MiB of output. No new installation
or environment activation is needed. Increment the output suffix for any rerun.
