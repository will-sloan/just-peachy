# Fixed application child for a same-Controller restart pair

Purpose: connect the qualified two-session lifecycle to the existing exact-PID,
private-desktop, renewable-lease child admission. The child starts no source
until its permit, CPU4 placement, supervisor/coordinator identities, immutable
code, source/model/audio bindings, desktop, disk/deadline and renewable lease
pass the unchanged ChildAdmission gates. No new approval bypass or ledger writer
is introduced. Preparation and actual launch remain different stages.

`restart_application_child.py` is an internal child entry point. Its inputs are
the coordinator's fixed transport/PERMIT.json path and exact launch nonce. The
permit binds the unchanged 13-field INPUT.json, including the full audio-only
job and composition. The child additionally requires the fixed restart cell ID,
S45_03_03 O0/O1 job, bounded duration and deterministic midpoint rule. It primes
the source, prepares one RestartApplicationCell, runs its two sessions through
`run_pair` with the same live admission callback, then closes the application.
It never calls the single-source run method or changes the full planned file.

Outputs are the existing private application/session receipts and transport/
CHILD_RESULT.json. A success requires the returned and persisted closure to
match, two completed sessions, closed Controller/worker, no errors or failure
capture, fixed pair/session receipt bindings, and no acceptance claims. Failed
prime/prepare/run/lease/cleanup retains a failure result when the validated
transport path exists. Constructor/desktop failures cannot write to an untrusted
path. A child collection success still requires independent parent/native/
delivery/engine/archive/viewport/resource review and proves no N4 acceptance.

## Dependency boundary

The child preserves **all 117** code records in RESTART_PLAN_CHECK_V1.json, plus
that qualification and these four files: **122 records**, below the unchanged
128-record limit. The coordinator's new native-prefix and result-review modules
are not imported by the child. Their manifests remain in the separately qualified
parent admission. No existing dependency was removed. This split avoids binding
every future coordinator-only reviewer into the child allowlist. ChildAdmission
still verifies every one of its records. The frozen prototype/source manifest
and model/runtime assets are additionally verified by its normal priming gate.

The future coordinator must launch this exact script on the private desktop in
a suspended owned Windows Job, bind the qualified interpreter and complete child
manifest, register ownership, issue the unchanged permit/lease, then resume.
It must supervise the lease, close/verify all child ownership, and independently
validate both session results before releasing the exclusive slot. This module
does not create a coordinator, claim a free slot, or authorize manual execution.
