# Selected panels from reviewed V3 scores

Purpose: qualify an immutable planning derivative that consumes the exact V3
method/scoring/reviewer family, including its bounded history and verified reused
main-bank prefix. This does not start an application, choose a winner, qualify
latency/resources, or accept N4/N5. Existing planners and active bank sources stay
immutable. Live CM5 validation remains deferred until reconnection.

`panel_scoring_admission_v3.py` requires both complete reviewed banks (7,680 main
and 1,536 modes), closed exact scorer/reviewer/metric owners, the qualified V3 code,
matching method/plan/score/report hashes, and the original denominator rules. It
rechecks the V3 method bank and each sealed score binding. It permits only the
qualified main-only `reuse_review` context difference. Other source, runtime,
component review, gallery, audio, qualification and code fields must match.
No reference text is read or supplied to the child.

`paced_panel_plan_v4.py` preserves the source-delivery application, fixed primary
roster, baseline plus at most five alternatives, 24 saved panel cases plus 16
timing repeats per candidate, and 13-field child allowlist. Its scoring policy is
part of the context/cache identity. `reconstruct` and `admit_plan` recheck exact
evidence; schema `n4-paced-panel-plan-v4` is intentionally distinct from V3.
Older runners/restart planners must not be used with it. Fresh dependent
derivatives and their qualification are still required before actual execution.

Inputs: accepted preparation/audio-only manifests; both completed V3 score
review `RESULT.json` files; an explicit selection JSON using schema
`n4-paced-selection-v1`; the qualified application source/prestart receipts;
the exact component assets, runtimes and research gallery already on disk.
The selection must bind both reviews, lead with A0/D0/E0, give each selected
composition an objective/rationale/limitations, and explain every exclusion.
Use measured reports to write this selection after both banks pass. Fixture
selections in tests are not recommendations or production evidence.

Outputs: fresh private planner directory with `ADMISSION.json`, `PLAN.json`,
`RESULT.json`; no source execution authorization or acceptance credit. The
probe writes its owner, five source snapshots, admission, test log and result
(or preserved failure) to a separate private directory. Public
`PACED_PANEL_PLAN_CHECK_V4.json` binds the reviewed development probe only.
