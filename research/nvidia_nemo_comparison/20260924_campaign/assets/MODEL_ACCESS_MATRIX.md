## Runtime and platform evidence

The pinned [NVIDIA native runtime](https://github.com/NVIDIA/NeMo-Speech.cpp/tree/97a15afa5caa9bce5baaa86c1184103877af4101) is Apache 2.0. Its required ggml submodule is pinned at `c03b4e2bcece5134827881af90242086daf75be5` (MIT), and the NVIDIA build recipe pins SentencePiece at `17d7580d6407802f85855d2cc9190634e2c95624` (Apache 2.0 with bundled Apache/BSD components). The selected CPU build excludes optional KenLM/Flashlight, Riva, llama.cpp/microphone, TTS dictionaries, OpenSSL, CUDA and normalization dependencies. Source/notice hashes, actual commands, outputs, status and binary hash are recorded in `runtime_receipt.json`.

Metadata-only artifact inspection in `asset_structure_receipt.json` confirms D1 is Sortformer v3 with eight speakers; A2/A3 are ASR GGUFs with SentencePiece BPE vocabularies, and A3 includes the tokenizer model. A1's NeMo archive includes its BPE tokenizer/model configuration under the official model terms, with no separate tokenizer license notice in the archive. E1 has model configuration and weights, no tokenizer; its 192-dimensional embedding head and 80-bin per-feature-normalized preprocessing differ from A1/D1's 128-bin front ends. Archive weight pickle objects were never deserialized. Tokenizer payloads are omitted from versioned receipts and remain inside the unchanged officially hashed artifacts.

Measured host: Ryzen 7 5700X3D, 8 cores/16 logical processors, 68,641,923,072 bytes physical RAM, RTX 3080 with 10,240 MiB VRAM, driver 610.62. The system PATH has CMake 3.21; Visual Studio's existing bundled 3.30.5 is sufficient. Existing WSL2 Ubuntu has Python but no `cmake`, `g++` or `ninja` on PATH. No WSL installation, feature enablement or global environment change occurred. The Pi remains powered off and untouched; no physical/ARM64 result is claimed.

D1 uses explicit `d1_low_latency.yaml`: chunk 9, right context 4, FIFO 264, speaker cache 264, update period 222. Its nominal 1.04 s is input buffering, never total latency. The pinned native runtime's `v3-streaming` preset uses chunk 13/right context 1, giving 1.12 s total input buffering; it must not silently replace the declared geometry. Predeclared later variants are chunk/right-context 6/2 (0.64 s) and 3/1 (0.32 s), keeping the model-card cache settings. Adapter delivery and compute must be measured separately. Artifact sizes are not RAM estimates.

[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/legalcode.en) requires attribution, license linkage and change indications. These weight licenses are recorded separately from runtime code licenses. Full official terms snapshots are hashed in `terms_receipts.json`; they are not interchangeable OSI code licenses.

For the unchanged E1 weights, attribution is NVIDIA, `speakerverification_en_titanet_large`, the linked official repository, CC BY 4.0; no modifications were made. For A1/A2 and any later X1 redistribution, retain: “Licensed by NVIDIA Corporation under the NVIDIA Open Model License”. No weights are included in Git or the handoff ZIP. The isolated runtime installation includes applicable source notices and bundled SentencePiece dependency notices. No evaluation datasets or denoiser models were requested; upstream source archives include incidental upstream sample fixtures, which are not campaign data and were never used.

The local Windows prefix also includes unmodified Microsoft VC runtime DLLs copied by CMake from the existing Visual Studio redistributable directory. They have separate proprietary terms, not Apache/MIT. [Microsoft's redistribution list](https://learn.microsoft.com/en-us/visualstudio/releases/2022/redistribution) identifies the permitted runtime files and conditions. This N1 handoff distributes no compiled runtime binaries; later external Windows packaging must retain/check the applicable Visual Studio terms and notices separately.

## N2 readiness boundary

Baseline plus D1 native route may proceed to the next stage's adapter/parity/screen work after common-front-end and corpus prerequisites pass. N1 staged exact artifacts and compiled the Windows CPU route; it did not compare models. A1/E1 require an isolated reviewed NeMo/export environment, not credentials. X1 and P2 remain lower-priority optional work. Native Windows compilation is not evidence of 2 GB CM5 feasibility. If a later environment install fails, record the exact failure and continue admitted backends without prompting indefinitely.
