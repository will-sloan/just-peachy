# Windows startup faults and actual controls

Purpose: test real Tk backend/mode/recipe buttons, explicit startup errors without a silent fallback, stopped-owner cleanup, recovery on restored settings, and explicit return to the baseline. This is a bounded saved-file experiment on the existing private desktop. It does not qualify every mode, enrollment, target performance or the full release.

Inputs: the unchanged E0-only application derivative, verified original assets and saved audio, accepted source ancestry, and fresh extension admission. The launcher derives from the immutable early-Stop V2 launcher and retains two CPUs total (4/14), one native thread/model, GPU off, 600-second admission, 240-second phase and 128-MiB cap. Original storage checks and combined 1-GiB output accounting apply. The builder verifies parent hashes and refuses existing generated files.

`controls_child_v1.py` operates the real Tk controls with `.invoke()` on a private desktop. It intentionally writes an invalid runtime document and then a nonexistent D1 model path only inside the newly isolated application data directory. It never edits actual models, bound source, production profiles or the original checkout. After restoring settings it starts the original saved file, stops after at least eight source seconds and requires all accepted audio to drain through ASR/D1 with captions and E0 calls. It uses neither microphone enumeration/capture nor playback. A real GUI error must be shown; controller-only failure is insufficient. An observed failure remains failed evidence.

Outputs: generated harness/launcher plus derivation receipt, private admission, fault snapshots, application results, exact process-lifetime receipts, and an independent review after closure. The test does not delete earlier evidence. A0 runs first; A2 follows only after independent review and exact owner closure. No concurrent numerical workers.
