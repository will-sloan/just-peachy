# Repeated operator session preparation

Purpose: allocate independent recording processes and retain their closed history without reusing an old recording root, admission, model process or failed reservation. These files are PREPARED, not a deployed or accepted launcher. V123's actual live/data composition remains a separate scoped pass.

## Files and inputs/outputs

- field_operator_session_plan_v1.py: pure exact allocation, measured-policy validation, sequential slot states and path-value rebasing. Inputs are a count1..4, immutable policy, slot records and roots. Outputs are a complete target+independent-host allocation or explicit rejection. Four slots reserve1,194,758,496B total; no policy is issued by this module.
- field_operator_session_ledger_v2.py: Linux/aarch64 broker ledger. Input is an existing fresh RELEASE.json with an externally issued measured policy and exact policy/release hashes. It holds a lifetime flock; publishes immutable RESERVED/STAGED/STARTED/CLOSED/FAILED records using pending files, file+directory fsync and no-replacement hardlink publication. It checks exact native parent/child/source closure before another recording and provides read-only SAVED-history descriptors. All failed/used slots remain charged. RECOVERED is a future reviewed record type; no recovery writer is provided. Reopening an existing ledger is inspection-only; it cannot silently resume after a crash.
- field_operator_parent_v7.py and field_operator_entry_v7.py: interactive derivatives of qualified V123 parentV6/entryV6. They remove only the automated qualification-driver imports/invocations/completion assertion and keep the actual installed Field UI, ownership ACK/barrier, limits, model/source/archive closure and Return. No automatic Open/New/Start/Save/transfer/Close. They still run one recording per admitted root.
- check_field_operator_sessions_v1.py: one changed Windows CPU14 pure-contract check. Its fresh output contains REGISTERED_OWNER.json and RESULT.json. It does not instantiate the native Ledger, GUI, Controller, model or source. Fixture policy/boot/digest values are never dispatch authority.

Native ledger publication, concurrent processes, crash/power-loss durability and repeated GUI execution are UNTESTED. A complete native broker must still issue/rebase and stage a fresh child admission, bind release capsules/method assets, register/ACK owners, supervise the child, mirror retained evidence, render historical data and keep local automatic recovery available. This is not an expiring research dispatcher relabeled as a finished user launcher. Streaming and Chunk52 live modes remain unavailable. Nonempty captions/gallery/offline/physical touch remain open.

The maximum is four attempts including failed attempts. The per-recording target146,919,980B and independent host151,114,284B remain unchanged. Metadata reserves RELEASE primary+pending (2*64KiB), six primary+pending16KiB records per slot and64KiB per metadata directory. The four-slot metadata maximum is1,310,720B on EACH side. Thus target588,990,640B, host605,767,856B, combined1,194,758,496B. Use the checked generated allocation as the arithmetic source of truth. No allowance has been issued and no old cap is changed. A new measured policy, fresh complete owners/lifetimes/census and source restore verification are prerequisites to native dispatch. Every batch ends within600s and the hard17:42:44Z boundary; no automatic extension.
