# Prepare one complete Saved replay on build26

Purpose: generate a fresh, explicit payload for one of the six retained backend
combinations. This host tool does not contact the Pi, start models, or invent a
kept recording UUID. It preserves earlier preparers and failed native sessions.

Inputs: actual host build26 package and native target, manifest SHA, observed
boot UUID, one actual kept session UUID and original session.json byte SHA,
operator backend ID, application Mode, fresh native/host labels and lifetime
60..600s. An optional `--session-json` verifies the exact PC mirror metadata.
Assigned-seat Modes additionally require the existing validated actual-person
seat draft; no identity or seating ground truth is invented.

Output: a fresh private preparation directory containing actual CPU14 owner,
finite8MiB/600s scope, exact source backups/independent restores, SOURCE_CLOSED,
ACTION.py/PAYLOAD.json with backups/restores, RESULT.command_argv and EXIT_INTENT.
The complete package inventory is hash-verified before pure profile imports.
The payload explicitly reserves256MiB target and256MiB PC; later native launch
must independently check current shared history/file allowance, resources,
leases, owners and floors. Preparing bytes is not issuing native admission.

Supported IDs: `pyannote_redimnet`, `pyannote_titanet`, `delayed_redimnet`,
`delayed_titanet`, `chunk52_2t_redimnet`, `chunk52_2t_titanet`. Source is `saved`.
Default Mode is `enrolled_names`; recorded-spatial choices are documented in
[the helper guide](README_NATIVE_SAVED_STABILIZATION_CHECK_V4.md). Every replay
uses the same full≤70s16kHz processed timeline. Original raw and recorded
beams/BMI are preserved and verified; they are not rerecorded or trimmed.

Use the emitted RESULT.command_argv only after the full dispatch preread is
clear. Finalize is a separate fresh payload with `--operation finalize`, the
same native label and exact input pins, and another fresh host dispatch label.
Neither command resets or renews old policies. `--discard-output` discards only
the newly completed replay output; copy/readback of kept sources is preserved.
Do not generate all payloads ahead of time or run backends concurrently.

`--self-check` compiles only preparer/helper and checks lexical rejects with
exact source backups; the focused V5 source review already includes these
sources, so do not rerun an unchanged healthy check for publication. All native
caption, model, spatial, performance and closure evidence stays pending until
observed on the CM5. EXIT_INTENT is not exact process-death proof.

The focused source checker `check_saved_payload_v5_source.py` backs/restores
both preparers and the unchanged helper, then compares whole UTF-8 source and
AST after the five explicit target/documentation/dispatcher replacements.
It loads no runtime, models or native source. Run once for changed-source review:

PowerShell: `& $Python -B "$Source/check_saved_payload_v5_source.py" --source $Source --output $FreshReview`

CMD/Anaconda: `"%PYTHON%" -B "%SOURCE%\check_saved_payload_v5_source.py" --source "%SOURCE%" --output "%FRESH_REVIEW%"`

Inputs are the stabilization source directory and one nonexistent private review
directory; outputs are source backups/restores, source pins, AST review and the
actual registered CPU14 owner. The scope is30 seconds/1 MiB. Exact process
closure must be independently recorded before any native dispatch preread.
