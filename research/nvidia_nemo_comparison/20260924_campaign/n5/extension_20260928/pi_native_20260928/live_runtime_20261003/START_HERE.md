# Just Peachy field-testing quick start

Production16 is installed with one unified **Just Peachy** Desktop shortcut. The actual desktop command, fullscreen480×800 interface, optional/ordinary policy controls and normal Exit passed the final closed native check. Prior owned shortcuts have verified archive/restore copies outside Desktop. Autostart remains disabled. Startup remains configured for desktop; no new reboot test was performed.

1. Open **Just Peachy** on the Desktop. It opens idle; the microphone stays off until **Start**.
2. On **Launch**, choose **Diarizer**, **Speaker embedding** and **Input**. For Nemotron, select its preset. Research modes require **Enable experimental configurations** and their accepted policy. The selector exposes configurations for guarded field testing, not a claim that every combination was measured.
3. For live input, press **Start** and accept temporary recording. Wait for model initialization. Normal source duration is at most5minutes (300seconds); the counter and status distinguish recording from final processing. You may press **Stop** earlier.
4. Wait for Stop, drain and process closure. Then choose **Save processed**, **Save raw + processed**, or **Discard audio**. Saving is deliberate; it does not happen when the microphone is opened. Raw save is available only when the displayed source capability is qualified for this recording. It is four microphones at16kHz PCM32, not four48kHz channels. The exact processed float32 timeline is preserved separately with replay audio.
5. Use **Recordings** to **Refresh**, page to **Older** recordings, **Open** captions, **Replay recording**, **Export**, or deliberately **Delete selected**. Replay recording streams the complete kept session and starts it using the current selected profile. It creates a new session; discarding that replay leaves its original intact. Select one or several recordings for Export and choose a new ZIP destination. Originals stay in history. Delete selected requires confirmation and affects only the selected recording.
6. Choose **Exit to desktop** when finished. Active work must close before Exit completes. The desktop-first startup and existing display rotation stay unchanged.

Recordings have unique persistent IDs and paged history. There is no four-recording limit: new sessions depend on declared disk reservation and the free-space floor. A failed/cancelled session does not spend a global slot; failure receipts are retained. No automatic deletion frees space. Retained v27/v28 rollback recordings are preserved separately and are not automatically imported into this new history.

The480×800 interface scrolls. Direction graphics describe audio relative to the device; room speaker identity is a separate result. Developer motion diagnostics and visual-zero controls do not recalibrate the hardware. The final check exercised actual controls programmatically; physical touch and visual quality were not separately qualified. See [motion guide](../../../completion_20261001/MOTION_GUIDE.md) and [mode guide](MODE_GUIDE.md) for controls and limitations.

All current measurements used a2GB CM5. Several short full pipelines and a300second live/save/replay workflow completed under the existing768MiB per-process address-space guard. The full-application hour04 failed before source EOF; an isolated Chunk52 diarizer hour passed. More4/8GB RAM may allow more simultaneous model residency but was not measured and does not promise faster CPU/thermal throughput. RSS, physical available RAM and virtual-address limits are different. See [RAM and resources](RAM_RESOURCE_GUIDE.md).

The optional second diarizer is admitted only for the measured live Pyannote/TitaNet configuration: enable experimental configurations, set the label revision window to60seconds, then select the optional refiner. Its displayed policy is300seconds source,120seconds load,60seconds drain,30seconds backlog and60seconds cleanup. Ordinary configurations retain120-second drain/backlog defaults. Other optional combinations remain unavailable. Actual live300 completed child EOF and closure but produced zero optional correction revisions; it is not a correction-quality or hour result. Sparse scheduling and late-label controls are experimental.
