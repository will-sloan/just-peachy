## Pipeline traced

The shared Sherpa model wrapper keeps one recognizer stream, accepts a waveform block, decodes while ready, obtains the current hypothesis and evaluates endpointing. In the examined unchanged wrapper, `prototype/vendor/edge_speech_pipeline/models.py:153–178` performs accept/result/reset; reset clears the stream and advances the utterance index. Final Stop drains with a short padding block and `input_finished`, rather than loading a new model. `models.py:192` onward calls the existing punctuation model on final text; text-format fallback punctuation is applied to a terminal revision, not to every partial callback.

The examined runtime consumes journal blocks by source cursor, revises the same native utterance as its hypothesis changes, publishes finals on reset and preserves the processed source intervals. S6d publishes initial text before slower identity/PnC revisions. S7 maintains source-ordered ASR revision versions, rejects a duplicate/older final and partial-after-final, retains matching prefix token identities and replaces the revised suffix. When speaker ownership changes, it can legitimately create a new child segment ID. The older retained application controller kept one latest row per native parent in an ordered mapping, so recomputing its current projection naturally removed absent children. The persistent runtime instead wrote each child independently; that is the confirmed regression point.

## What remains a hypothesis

A `particul` partial becoming `particular` within one native parent is an ordinary hypothesis revision. It must replace that parent's suffix rather than append a second phrase. A recognizer reset occurring during a word could instead split speech between two native parents; deciding whether that caused the reported acoustic defect requires the matched source audio, endpoint reason and dispatch timeline. A spelling-based splice across parents would risk deleting legitimate repetitions or combining unrelated words, so no such rule is introduced.

The approximately 20-second final boundaries are compatible with the shared configured maximum-utterance rule. They do not prove that a word was cut, that a model was reloaded, or that PnC caused the fragmentation. Current span terminal punctuation appears on four rows; obsolete rows contain no terminal punctuation. That distribution supports attribution/storage/layout as the main observed block-fragmentation cause, while acoustic recognition and punctuation quality remain separate measurements.

The pre-Nemotron `509195b8` model wrapper and endpoint defaults match the examined shared wrapper/config. This audit therefore does not attribute the confirmed persistence regression to a new recognizer or recommend replacing speech models. Useful older behaviour to recover is parent-key replacement and the retained small-font, stable-mark UI—not a different speech backend.

## Candidate invariants and review points

1. One native parent owns a complete current source partition. Replacement validates every part, retires only that parent's missing children and commits or rolls back as a unit. Identical final delivery is idempotent; a real repeated phrase inside the source partition is preserved.
2. Display revision order is distinct from ASR text revision because identity and final punctuation may revise unchanged raw text. Zero-valued user view counters are not used as a positive monotonic storage version; the engine integration uses a positive native display version when available, otherwise the storage change counter.
3. Paragraphs retain all source spans in `_caption_parts`. Their IDs use native parent plus first token, while names, ownership IDs and suffix text may revise. The helper joins text with spaces only; it does not remove words or infer new timing.
4. Manual history retains a bounded parent set; old labels can update, new speech cannot replace the window, and a page boundary protects the existing paragraph mark when older text is prepended. A queued smoothing frame cannot put an old live tail over manual history. Paging holds at most 80 spans, repartition refresh at most 120 parts.
5. Legacy recordings retain their indexed evidence. Their exact database-parent fallback is used for manual refresh, preventing accidental row disappearance. No retrospective deletion, old-recording source-order repair or old-export cleanup is claimed.

Candidate locations: `caption_paragraphs.py:48` continuity, `:76` provenance-preserving aggregate, `:109` bounded grouping; `classic_frontend.py:46` recorded row projection, `:132` Compact19 typography, `:284` follow/window control, `:313` older-page anchor boundary, `:330` prompt bounded reads; `mature_frontend.py:28` retained renderer integration, `:39` scroll/history control, `:51` Return to live, `:105` steady pending label.
