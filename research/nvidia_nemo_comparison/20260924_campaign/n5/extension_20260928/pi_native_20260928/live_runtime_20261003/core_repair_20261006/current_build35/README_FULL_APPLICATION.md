# Build21 stabilization

Purpose: repair chooser-to-portrait startup and physical XVF/raw startup, reduce
normal choices to useful named backends, extend seat adapters and replay recorded
spatial evidence. Preserve the mature GUI, build21 rollback, manual Stop, data,
model/gallery separation, source/ownership/storage guards and disabled refiner.

Inputs are the immutable build21 package, exact current diagnostics, selected
local model assets and closed rich recordings. Outputs are new versioned source,
bounded native receipts, the operator backend matrix and updated mode/handoff
guides. Read STABILIZATION_CHECKLIST.md. No historical research campaign starts.

Host tools use CPU14 and early actual process registration before project reads.
Source/configuration changes need verified backups and independent restores
before native use. A source or GUI-only check is not a microphone/backend pass.

CMD and Anaconda Prompt use the same explicit Python executable and arguments,
in double quotes, without PowerShell's leading `&`. No download or activation
is required. This inspection reads bounded startup/source failure records and
current process identities; it starts no GUI, microphone or model and writes no
Pi payload. Output is a new private operation with full preread and raw/closure.
The inspection JSON has exactly `package_manifest_sha256`; the inspector itself
bounds requested files and returned tails. Do not reuse failed labels or admissions.

`check_stabilization_faults.py` reads the actual preserved settings pin and tests
only the new settings adapter and zero-sample failed-Start helper. Its output is a
fresh private compact PASS/failure with early CPU14 owner and verified source
backups/restores. Fixture paths exercise partial/nonempty failure preservation;
they are not microphone proof.

`build_stabilization_package.py` takes the exact private build21 package plus the
explicit new modules in this directory and emits a separate build22 package,
archive, provenance, exact member hashes and independent expanded restore. It
keeps the original packaging/member/CPU/disk limits. It deploys nothing itself.
CMD/Anaconda equivalents are the same quoted Python path followed by
`check_stabilization_faults.py` or `build_stabilization_package.py`; no arguments,
activation or download are needed. Native stage/test/activation use fresh guarded
payloads and labels and will be documented before execution.

Per-module READMEs document the new chooser, seat and saved spatial interfaces.
