# Runtime integration tests

`test_runtime_integration.py` verifies the local orchestration/storage boundary
without importing native models, opening a GUI, capturing audio, using a network,
or contacting a Pi. It uses synthetic samples, owned temporary directories,
explicit fake-process fixtures, and one real synthetic Python child process.
The actual child is pinned to CPU 14 and records its real PID, numeric Unix
creation time, and affinity before reading project code or requests.

Inputs are the Python environment, an isolated evidence directory, and a
synthetic binding generated by each test. Outputs are unittest diagnostics,
`REGISTERED_OWNER.json`, and `TEST_RESULT.json`. Per-test synthetic stores and
child receipts are cleaned up only within their own temporary directories. No
existing recording or deployment is changed. Python 3.11+ and `psutil` in the
already-qualified `.edge-speech-env` environment are used; do not install a new
environment for these checks.

## What is checked

- `launcher.Manager`: gated admission, process-launch failure receipts, one
  owned worker, a Stop requested before child registration, pending Close,
  malformed child-result handling, deadline Stop requests, output-reader join,
  direct-child reaping, exact nested source-owner closure, retained recordings,
  restart, persistent current-launch recovery, and headless stop/keep actions.
- The visible spatial channel: the real Manager collector retains the latest
  bounded spatial message in memory, leaves diagnostic log bytes unchanged,
  controls the source-owned visibility marker, and passes the retained allocator
  variables before child execution. These checks create no GUI or sensor.
- `worker.run_owned_session`: injected synthetic success, run failure, cleanup
  failure, and artifact-registration failure. Each path releases the storage
  lease and preserves a final result/failure receipt. Physical process closure
  remains the manager's responsibility, not a claim made by a worker receipt.
- `storage.latest_captions` and `launcher.CaptionView`: the newest bounded tail
  after more than 100 captions, stable-ID revisions, and no repeated rendering
  when the revision cursor is unchanged. SQLite uses indexes on caption sequence
  and caption-revision events. Full history remains paged and preserved.
- `runtime_support.SegmentedText`: hard per-segment bounds, cumulative disk
  allowance shared across writers, queue overflow, preservation of the accepted
  prefix after producer rejection, and final flush/fsync failure reporting.

These tests establish synthetic functional behavior. They do not qualify native
throughput, speaker accuracy, microphone source restoration, live refinement,
storage endurance, or recovery from a hung native call. At the finite process
or Stop/drain deadline, the manager can request whole-service kill only after
checking the exact owned InvocationID, ControlGroup, MainPID, process boot/start
identity, and its own cgroup membership. Tests mock systemctl; they never signal
a native service. The external native scope wrapper independently enforces
RuntimeMaxSec and must publish actual unit/source closure. A kill request does
not imply successful microphone restoration. Provisional correction remains
disabled until its separate native admission is implemented and passed.

## Integration contracts

`CaptionView(store, limit=40).refresh(session_id)` returns whether the display
changed. Its `rows` contain the latest captions in chronological order, and its
revision cursor notices corrections to existing caption IDs. It does not fetch
the first 100 rows or walk old history on each UI tick.

`run_owned_session(store, spool, session, owner_directory)` accepts a session
with `run()`, `fail(reason)`, `close()`, `stop_event`, and `work`. It monitors the
owned `STOP` marker, closes the session, streams native-file registration,
finalizes the storage spool, and publishes `RESULT.json`. Its return value is
0 for logical success or 1 for a preserved failure. Native bootstrap and model
admission are still performed by `worker.main()`.

The worker initially uses a 32 MiB soft file ceiling and an inherited-safe hard
ceiling derived from actual free space minus the 5 GiB floor. After the request
is validated, `file_size_plan` derives a finite limit from existing SQLite size,
the explicit session metadata reservation, a separately counted metadata/journal
copy, and bounded journal overhead. It rejects a plan exceeding current free
space above the configured reserve or the inherited hard ceiling. This avoids
a fixed 32 MiB lifetime cap on shared history while preserving finite native
file allowances. The file plan is saved as `FILE_ALLOCATION.json`.

## Prepared headless native interface

Invoke these options through the owned native scope wrapper after its explicit
deployment/admission steps. Do not run a model or microphone on the Windows host.
The wrapper supplies `--binding`, `--data-root`, `--unit`, and `--unit-ownership`.

History's **Replay recording** streams every segment of a selected kept session,
using the current profile. `--saved-session-id` and optional current
`--saved-store-root` provide the same headless input; `--saved-path` remains the
separate single-WAV option. The request rejects both at once. See
`README_SAVED_REPLAY.md` for source leases, bounded disk reads and exact clocks.

```text
--headless --input-source live --diarizer pyannote --embedding redimnet --maximum-session-seconds 60 --stop-after-seconds 60 --keep-processed
--headless --input-source saved --saved-path /absolute/processed.wav --diarizer nemotron --nemotron-profile current_delayed --embedding anonymous --maximum-session-seconds 300 --keep-processed
--headless --input-source live --maximum-session-seconds 3600 --developer-soak --max-drain-seconds 1800 --max-backlog-seconds 120 --keep-processed
```

`--request-stop` targets only `CURRENT_LAUNCH.json` through an idempotent
`STOP_REQUEST` marker. Headless success waits for worker reaping and exact source
owner disappearance before preserving processed audio. Normal saved input stays
processed only. Normal live raw can be temporarily spooled only with a passed,
enabled raw binding; the GUI then offers Save processed, Save raw + processed,
and Discard. Raw source-only qualification never enters the full model worker.

The same launcher exposes Developer controls and corresponding CLI fields:
`--embedding-schedule continuous|sparse_clean_turn`,
`--embedding-refresh-seconds 2`,
`--speaker-attribution retained|single_d1_late_labels`, and
`--revision-window-seconds 30`. Continuous embedding and retained attribution
remain the defaults. Sparse scheduling requires experimental Nemotron with a
named ReDimNet/TitaNet backend; late labels require experimental Nemotron.
Profile validation rejects incompatible combinations. The provisional
correction checkbox remains disabled pending native admission. Host tests do
not claim native GUI or speaker-quality validation.

Every Start validates release authorization and requires enough remaining
owned-service lifetime for the entire session deadline plus 150 seconds. The
worker independently verifies authorized asset hashes before importing the
engine. The desktop exits after the receipt's finite idle interval (normally
300 seconds) only while no worker is running; clicks and keys reset the idle
timer. Recording count does not affect admission.

`resource_snapshot()` retains RSS, available RAM, CPU seconds and thread
count, and adds `virtual_bytes`, `peak_virtual_bytes`, `swap_bytes`, `pss_bytes`,
`pss_sample_age_seconds` and `pss_sampled_monotonic_sec`. Linux VmSize, VmPeak,
VmSwap and smaps-rollup PSS are sampled at most once per second per process.
Unavailable PSS/swap stays null. Snapshots explicitly report
`scope: current_process` and `whole_unit_aggregate: false`; these worker
metrics are not totals for the GUI/source/service. An external unit monitor is
needed for whole-unit RAM evidence. `vm_peak_bytes`/`vm_swap_bytes` remain
compatible aliases. The focused test proves cache reuse, refresh and missing
metric behavior.

`DiskBudget(maximum_bytes, reserve_bytes=5*1024**3, reserve_fraction=0)` tracks
one shared logical metadata allocation. Pass the same instance as
`SegmentedText(..., budget=shared_budget)` to every sink sharing that allocation.
Per-writer `maximum_bytes`, `segment_bytes`, and `queue_bytes` remain enforced.
The controller must allocate separate finite portions for SQLite metadata and
other native outputs; a shared text budget alone does not reserve the complete
session. The filesystem floor is checked against actual free bytes when writing.

Text index receipts use `segment_count` and `segment_pattern` (for example
`events.jsonl.%06d`), so the writer does not retain an unbounded list of names.
Iterate integer indices from zero to `segment_count - 1` to recover segment
paths. A record larger than a segment is rejected explicitly. An error receipt
never says `complete: true`, including when all previously accepted records
drain successfully after a later rejected record. `completed_bytes` measures
written bytes; successful final fsync plus `complete: true` establishes the
successful publication boundary.
