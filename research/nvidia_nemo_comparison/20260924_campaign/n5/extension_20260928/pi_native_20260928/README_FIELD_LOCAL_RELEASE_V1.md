# Finite local release lifecycle V1

Purpose: specify independent finite recording, local-backup, host-backup and launch/restart allocations for a future local release. This is prepared source, not an activated launcher. Existing research policy and WINDOW_V5 remain immutable. No new native policy, admission, root, GUI or recording is created by these modules or the host check.

The plan permits 1–4 independently reserved one-recording broker roots and 1–16 launch slots. Every recording reserves the full existing broker allocation, an independent complete local mirror, and the existing host mirror. Failed, deleted, unused-small and incomplete recordings never return reservation credit. Each immutable primary and pending metadata file has its own maximum. Local code has a separate 16-file/2MiB limit, with 128KiB members. This code is outside the old 64-member recording capsule; it does not increase that limit.

The proposed installed-release limit is 24 hours per manually opened idle launch, with no automatic restart or capture, finite launch count, unchanged 120-second audio/300-second child/600-second session batch limits and fixed CPU/RAM/free-space floors. This is a specification only: no such production lifetime has been admitted or activated. The implemented qualification-operation validator still enforces at most600seconds, closure/backup included, ending before2026-10-01T17:42:44Z. It explicitly rejects a manual-production purpose. A real local activation/manager adapter is still required; no Boolean readiness flag grants permission.

field_local_release_plan_v1.py validates exact policy shape, full allocations and pure lifecycle state. A new recording requires previous physical closure AND independent verified backup. Failed recordings with closure/backup remain failed and consumed. Restart requires a new launch slot and the prior exit record. Recovery classification preserves missing-owner gaps and active hardware; its inputs are observations to be supplied by an actual verifier, not evidence generated by this pure function. Actual native V129 health evidence remains separate.

field_local_release_files_v1.py is an UNEXECUTED native metadata primitive. Its Journal API takes an exact existing release-policy hash and a fresh qualification operation. CPU3/native aarch64, lifetime directory flock, exact directory/file membership, per-file/aggregate/cardinality limits, 16KiB writes, fsync, no-replace link publication, readback, permanent instance fault latch and pending-file rejection apply. Reopening cannot erase/overwrite records or impersonate a prior owner. The current primitive requires an empty backups directory because the real local mirror consumer is not wired. It does not verify arbitrary supplied closure facts or issue activation; an actual manager must bind source/owner/systemd/backup receipts before publication. No native durability/concurrency/powerloss/recovery claim follows from the host check.

Inputs: counts, canonical release and distinct broker roots, exact manifest/activation-plan hashes, fresh measured total output/payload counters and explicit limits. The activation PLAN hash avoids circular policy/activation hashes; future actual ACTIVATION must bind the finalized policy and observed lifecycle. Output: pure allocation/state decisions or native immutable JSON metadata after separate admission. No weights, audio, identities or private gallery data are copied.
