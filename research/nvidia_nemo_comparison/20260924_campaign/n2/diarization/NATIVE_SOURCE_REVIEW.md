# Reviewed D1 execution surface

The inspected official source revision is `NVIDIA/NeMo-Speech.cpp@97a15afa5caa9bce5baaa86c1184103877af4101`; the archive and dependency hashes are recorded by N1 in `assets/runtime_receipt.json`. This review used those pinned local files, not mutable CLI defaults. The official model card snapshot is `local/assets/metadata/D1/README.md`, pinned to `nvidia/Nemotron-3-Diarization@f667ed73aee57d40cc39428eb768b4fd87a0a29e`.

Reviewed paths and consequences:

- `include/nemo_speech/diar.h` and `src/asr/c_api.cpp`: standalone model/stream handles, explicit geometry overrides, push, finish, probability frame count/base/copy, teardown. The standalone create calls only `Diarizer::load`; no ASR/TTS checkpoint is selected or loaded. Python binds these exact C signatures through ctypes.
- `src/asr/diar/diarizer.cpp`: CPU selection is explicit `gpu=-1`; each stream carries its own model-specific resampler/state. This adapter admits only 16 kHz mono and therefore requires no resampling.
- `src/asr/diar/diar_pipeline.cpp`: regular pushes run only when the complete chunk plus right context is available. The V3 path emits native high-resolution probabilities directly, without the V2 four-channel birth gate. This adapter never uses provisional preview or full-file offline calls. Probability increments are immutable under the selected push/finish path. A new independent stream resets the speaker cache; ordinary turns do not.
- `src/asr/features/fe.cpp`: frames are released when their centered FFT support is available. At this checkpoint's 16 kHz/512 FFT/160 hop, the first complete model chunk requires 16,736 / 10,336 / 5,216 samples for the three declared profiles. Real neural boundary checks confirmed no output one sample earlier.
- `src/asr/diar/diar_pipeline.cpp` finalization: the feature tail is padded after pre-emphasis equivalence and then the remaining chunk is run on the existing state. The final native endpoint frame is retained. On the 12-second exact-duration panel the native path emits 1,201 frames and NeMo's valid feature length is 1,200. The parity comparison records and retains the unpaired frame rather than silently trimming the native artifact.
- `src/runtime/ggml/session.cpp`: the official graph helper hardcodes four threads. N2 creates a separate source/build and changes that single call to one. The Windows text write also normalizes this copied file's 954 LF line endings to CRLF; there is one semantic source change. The exact before/after file hashes, commands, compile logs, DLL hashes and original revision are in `NATIVE_BUILD_RECEIPT.json`. N1 source/build and frozen prototype remain untouched.
- `src/runtime/ggml/backend.cpp` lines 67–101: explicit GPU selection enumerates available GPU backends, requires the requested index, and throws if missing or initialization fails. It does not silently select CPU when GPU was requested. The scheduler still includes CPU support for operators. The separate CUDA build uses existing CUDA 12.6/SM86, and the adapter rejects mixing runtime directories in one process because Windows dependency DLL basenames overlap. `CUDA_BUILD_RECEIPT.json` and `CUDA_PARITY_RECEIPT.json` identify this distinct desktop route.
- The runtime's raw probability compaction triggers after roughly 20 minutes and requires a safe all-speaker silence gap. If no such gap occurs, it retries later. Long-session memory behavior is therefore not proven by this short panel; neither the runtime nor adapter may be advertised as a strict end-to-end 2 GB bound.

The pinned GGUF structure audit reports 360 tensors, Sortformer version V3, eight speakers, 128 mel features, encoder hidden size 512, 31 layers, encoder subsampling 8, output subsampling 1, upsampling 8 and learnable silence. The adapter additionally verifies the exact Q8 SHA256 and native eight-channel/10 ms interface before accepting audio. It cannot load an older four-speaker Sortformer under D1's name.

The default official C segmentation parameters are described in source as legacy callhome-tuned values. The adapter deliberately exposes raw probabilities and a declared 0.5 diagnostic threshold instead of presenting those defaults as validated for this corpus. This is an implementation choice, not calibration evidence. Short/overlap windows remain observable, while personal naming must use separate embedding evidence and conservative rejection.

Eight arrival-ordered anonymous slots are an architectural capacity, not an eight-person identity gallery. A ninth physical person can merge into existing slots. The adapter reports that overflow is not detectable from eight probabilities alone; it never recycles a slot because an evaluator knows a person left. Stored galleries are separate, model-specific representations.

The official NeMo reference uses the pinned `NVIDIA-NeMo/Speech@cf724ac337d1ebc7d0dda1e23fb80916f52927a5` model, feature and Sortformer module code reviewed locally before execution. The runner calls `forward_streaming_step` with persistent synchronous state. It recomputes features only from arrived prefixes, with no future waveform, transcript or reference speaker input. It disables inference dither, uses CPU FP32, and records the exact restored checkpoint and Python source hash. Recomputed-prefix frontend cost is included; this route is a parity diagnostic, not a source-paced deployment claim.
