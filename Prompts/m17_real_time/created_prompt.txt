Milestone goal:
Add a genuine real-time microphone prototype that continuously captures audio while an inference worker processes completed windows through the existing `PipelineRunner`. It should avoid capture gaps caused by ASR runtime, measure lag/backlog, and print/write live predictions and diagnostics.

Implementation requirements:
1. Inspect existing M17 live mic script, pipeline, ASR adapters, enrollment/matching boundaries, tests, and report patterns before editing.
2. Add a new CLI script rather than replacing `live_mic_smoke.py`.
3. Use a producer-consumer architecture:
   - producer continuously captures microphone frames using `sounddevice.InputStream` or equivalent callback;
   - frames are buffered into fixed inference windows;
   - completed windows are queued for a background inference worker;
   - the worker writes each window to a WAV and calls `PipelineRunner.predict(...)`;
   - capture must continue while inference is running.
4. Preserve the file-backed pipeline contract by writing each inference window to WAV and passing that path as `record["inference_audio_path"]`.
5. Support options like:
   - `--config`
   - `--run-id`
   - `--duration-sec`
   - `--window-sec`
   - `--hop-sec`
   - `--sample-rate`
   - `--speaker-label`
   - `--recording-id`
   - `--device`
   - `--output-dir`
   - `--keep-audio`
   - `--dry-run`
   - `--max-queue`
   - `--drop-policy` with choices like `drop_oldest`, `drop_newest`, `block`
6. Windowing behavior:
   - `window-sec` is the audio duration sent to inference.
   - `hop-sec` is the spacing between inference windows.
   - If `hop-sec < window-sec`, support overlapping windows.
   - If `hop-sec == window-sec`, support contiguous chunks.
   - Do not require transcript stitching in this milestone, but record enough metadata to support it later.
7. Output structure should be run-like:
   - `runs/live_mic_realtime/<run_id>/audio/window_0001.wav`
   - `runs/live_mic_realtime/<run_id>/predictions/utterances.jsonl`
   - `runs/live_mic_realtime/<run_id>/predictions/diagnostics.jsonl`
   - `runs/live_mic_realtime/<run_id>/summary.json`
8. Each prediction row must use the required Evaluation Tool fields. Diagnostics should include:
   - `window_index`
   - `capture_start_monotonic`
   - `capture_end_monotonic`
   - `inference_start_monotonic`
   - `inference_end_monotonic`
   - `capture_to_prediction_latency_sec`
   - `asr_realtime_factor` if available
   - queue depth at enqueue/dequeue
   - dropped-window count
   - `inference_audio_path`
9. Print concise live transcript lines as predictions complete, including latency and backlog.
10. Gracefully handle:
   - missing `sounddevice`;
   - no microphone permission/device;
   - missing Whisper package;
   - missing Whisper model asset when downloads are disabled;
   - ASR slower than capture, with explicit backlog/drop diagnostics.
11. `--dry-run` must work without microphone hardware or Whisper assets by using synthetic audio frames and a no-op/fake pipeline mode.
12. Do not silently present no-op transcripts as real ASR.
13. Add a realtime Whisper tiny config with downloads disabled by default.
14. Tests must use fake/injected capture and fake pipeline behavior. No test may require a physical microphone, OS permission, or Whisper assets.
15. Tests must verify:
   - capture and inference are decoupled, meaning capture can enqueue multiple windows while fake inference sleeps or blocks;
   - generated records preserve `recording_id`, `utt_id`, `start_sec`, `end_sec`, and `speaker_label`;
   - WAV paths are passed through `inference_audio_path`;
   - JSONL predictions use the required fields;
   - diagnostics contain latency/backlog/drop fields;
   - dry-run works without mic or Whisper;
   - missing microphone dependency is reported cleanly;
   - queue overflow/drop policy behavior is deterministic.
16. Keep edits narrowly scoped. Avoid broad refactors.
