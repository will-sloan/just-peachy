Main requirements:

1. Simple WAV CLI
- Implement:


python scripts/transcribe_wav.py /path/to/audio.wav


- It should call the existing `PipelineRunner.predict()` directly.
- It must not create Evaluation Tool run folders by default.
- It must not run scoring, plotting, or report generation.
- It must print the transcript result to stdout.

2. Input handling
- Accept one or more WAV paths.
- Validate each path exists and has `.wav` suffix.
- Use `soundfile` or existing audio utilities to infer duration when possible.
- Build a synthetic record per WAV with:
  - `recording_id`
  - `utt_id`
  - `inference_audio_path`
  - `start_sec`
  - `end_sec`
- Default `recording_id` and `utt_id` should be based on the WAV stem.
- Add optional overrides:
  - `--recording-id`
  - `--utt-id`
  - `--start-sec`
  - `--end-sec`
- For multiple WAVs, disallow single-value `--recording-id` / `--utt-id` unless the design clearly handles unique IDs safely.

3. Config selection
- Default to `configs/inference/e2e_real_local.yaml` if present.
- Add:

--config configs/inference/e2e_real_local.yaml

- Add:

--smoke-safe

to use `configs/inference/e2e_named_transcript.yaml` for dependency-light smoke testing.

- Do not download model assets.
- Missing model assets must fail with a clear, actionable error.

4. Output modes
- Default stdout format should be concise text:


[Unknown] transcript text here


- Add:


--format text
--format json
--format jsonl


- `json` should emit a JSON object for one WAV and a JSON list for multiple WAVs.
- `jsonl` should emit one JSON object per WAV.
- JSON output should include:
  - `recording_id`
  - `utt_id`
  - `audio_path`
  - `start_sec`
  - `end_sec`
  - `speaker_label`
  - `text`
  - optionally `segments` only when requested
- Add:


--segments


to include segment/transcript item details in JSON/JSONL output.
- Default text output should not include diagnostics noise.

5. Diagnostics
- Do not write diagnostics by default.
- Add optional:


--diagnostics /path/to/diagnostics.jsonl


- When provided, write pipeline diagnostics to that JSONL file.
- Diagnostics must be separate from stdout.
- Do not break the existing evaluator diagnostics behavior.

6. Speaker enrollment
- Add optional:


--enrollment-db artifacts/enrollment/enrollment_db.json


- This should override the enrollment DB path in the selected pipeline config for this direct CLI run only.
- If the DB is missing or empty, the command should still work and label speakers as `Unknown`.
- Do not implement new enrollment logic in this milestone.

7. Exit behavior
- Exit `0` when all WAVs process successfully.
- Exit nonzero if any WAV fails.
- For multiple WAVs, process independently and summarize failures to stderr.
- Keep stdout machine-readable when `--format json` or `--format jsonl` is selected.

8. Preserve existing Evaluation Tool behavior
- Do not change `run_evaluation.py full` behavior except if a tiny shared helper is clearly justified.
- Do not change `predictions/utterances.jsonl` contract.
- Do not change scoring/report behavior.
- Avoid broad refactors.
