Implementation requirements:
- Design the simplest safe scheduler:
  - one subprocess per job
  - explicit `CUDA_VISIBLE_DEVICES`
  - configurable `max_workers`
  - configurable per-job timeout
  - unique run/output directory per job
  - serial fallback mode for debugging
- Avoid loading multiple large models in one process unless deliberately configured.
- Each job must get an isolated config snapshot and output folder.
- Support a sweep config that compares multiple ASR or speaker embedding models over the same dataset subset.
- Record runtime metadata where available:
  - GPU name
  - VRAM
  - peak memory
  - average utilization
  - job duration
  - failures
  - retries
  - timeout status
  - assigned CUDA device
- If GPU telemetry is unavailable, record `null`/`unavailable` fields rather than failing the whole scheduler.
- Scheduler failures must be reported clearly and must not silently lose results.
- Two small jobs must be able to run independently without overwriting each other.
- Keep the design modular and PyTorch-native-compatible for future Raspberry Pi, ExecuTorch, or custom-hardware work.

Validation metrics/reporting:
- Throughput: audio hours processed per wall-clock hour.
- Failure rate under parallel load.
- GPU memory headroom.
- Speedup vs serial baseline when comparable data exists.
- Reproducibility: each job has isolated config and output folder.
