# Stage 10 Speaker Protocol

## Purpose

This package builds and evaluates the reproducible speaker-recognition protocol for every qualified embedding backend. It derives immutable enrollment, calibration, known-evaluation, unknown-evaluation, clean-probe, and degraded-probe manifests from the frozen Stage 2 speaker panel. It then creates backend-specific enrollment centroids, calibrates a cosine operating threshold without using evaluation probes, and produces verification, closed-set identification, open-set identification, and `Unknown`-rejection results.

It does not perform diarization science, download models implicitly, reuse enrollment vectors between backends, or copy a reference identity into a prediction.

## Inputs

- `benchmarks/v1/speaker_protocol.parquet`: frozen Stage 2 source selection.
- `configs/automated_evaluation/speaker_protocol.v1.yaml`: Stage 10 split, privacy, enrollment, calibration, and metric policy.
- Existing local model assets and the qualified component YAML files for ECAPA, Resemblyzer, Sherpa-ONNX, and WeSpeaker.
- A typed observation NPZ containing embeddings generated from the exact protocol item IDs. Degraded rows must use audio generated by an approved campaign condition; the clean source path must never be presented as degraded audio.

## Outputs

Versioned manifests are written under `benchmarks/stage10/<tier>/`. A result directory contains:

- `protocol_run.json` and `backend_identity.json`;
- typed embedding NPZ files and `embeddings/index.parquet`;
- backend-specific enrollment metadata, index, and centroid NPZ files;
- similarity scores and threshold sweeps;
- calibration results;
- verification decisions and identification rankings;
- `unknown_rejection_decisions.parquet`, preserving the literal `Unknown` label;
- failure records;
- summary and grouped metrics with counts and confidence intervals;
- SHA-256 checksums.

No pickle files are used. Embeddings, centroids, and similarity tables are classified as biometric-sensitive artifacts.

The smoke command invokes each matching isolated interpreter automatically. To extract clean protocol embeddings manually in a specific environment:

```bat
rem ECAPA
..\..\.venv\Scripts\python.exe run_evaluation.py speaker-protocol extract --manifest-root benchmarks\stage10\small --component speechbrain_ecapa --output-root runs\speaker_extract\speechbrain_ecapa

rem Resemblyzer
..\..\.stage8-envs\extended-local\Scripts\python.exe run_evaluation.py speaker-protocol extract --manifest-root benchmarks\stage10\small --component resemblyzer --output-root runs\speaker_extract\resemblyzer

rem Sherpa-ONNX speaker embeddings
..\..\.stage8-envs\onnx\Scripts\python.exe run_evaluation.py speaker-protocol extract --manifest-root benchmarks\stage10\small --component sherpa_onnx_speaker_embedding --output-root runs\speaker_extract\sherpa_onnx_speaker_embedding

rem WeSpeaker
..\..\.stage8-envs\wespeaker\Scripts\python.exe run_evaluation.py speaker-protocol extract --manifest-root benchmarks\stage10\small --component wespeaker --output-root runs\speaker_extract\wespeaker
```

Direct extraction intentionally selects only clean rows. For a scientific run, the campaign executor must first materialize every approved degraded probe and retain the same global item ID. Once a complete observation bundle exists, evaluate it with:

```bat
..\..\.venv\Scripts\python.exe run_evaluation.py speaker-protocol evaluate ^
  --manifest-root benchmarks\stage10\small ^
  --observation-bundle automated_runs\<campaign_id>\analysis\speaker_observations.npz ^
  --backend-identity automated_runs\<campaign_id>\analysis\backend_identity.json ^
  --output-root automated_runs\<campaign_id>\analysis\speaker_protocol

..\..\.venv\Scripts\python.exe run_evaluation.py speaker-protocol validate ^
  --result-root automated_runs\<campaign_id>\analysis\speaker_protocol
```

Do not add `--allow-overwrite` unless replacing a known generated result is intentional. A changed backend, model hash, config hash, embedding dimension, preprocessing policy, or threshold policy requires a separate enrollment and result directory.
