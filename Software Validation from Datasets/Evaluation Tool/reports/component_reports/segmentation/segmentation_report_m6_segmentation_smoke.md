## Summary

M6 adds a swappable `SegmenterBase` interface and a deterministic
`VADChunker`. The chunker converts existing `SpeechRegion` rows into existing
`AudioSegment` objects using configurable `min_chunk_sec`, `max_chunk_sec`,
`merge_gap_sec`, `left_pad_sec`, `right_pad_sec`, `clip_to_record_bounds`, and
`target` parameters.

The implementation merges adjacent VAD regions before padding, drops tiny
merged regions, pads and clips to record/audio bounds, splits long chunks with
deterministic even windowing, and returns segments sorted by start time.

`AudioSegment` does not carry `recording_id` or `utt_id`, so M6 preserves
traceability with local `SegmentTrace` rows generated by `trace_segments()`.
This avoids broad contract changes while making every segment traceable back to
the selected Evaluation Tool row.

The current config exposes one policy with `target: asr`. Separate ASR and
speaker-embedding chunk policies are intentionally deferred until speaker
embedding adapters exist.

## Runner Contract Preservation

- `ExternalStubRunner.predict_one(record, run_config, logger)` still returns the
  existing `UtterancePrediction` type.
- The pipeline still receives one selected metadata row at a time.
- `record["inference_audio_path"]` remains the audio source.
- `recording_id`, `utt_id`, `start_sec`, and `end_sec` are preserved in final
  predictions.
- `predictions/utterances.jsonl` schema is unchanged.
- No scorer, plot generation, report generator, GUI, CLI, dataset registry, or
  normalized metadata behavior was redesigned.

## Blockers

- The CLI does not yet expose inference component selection, so the full
  Evaluation Tool smoke verifies the external-stub runner path but does not
  exercise `vad_chunks` through a user-facing CLI option.
- The selected CMU Arctic smoke row reported `missing_audio_count=1`; the
  external stub does not verify audio existence, so this did not block scoring
  or reporting. Direct synthetic smoke was used for M6 segmentation diagnostics.

## Incomplete

- Separate ASR and speaker-embedding chunk policies are not implemented because
  speaker embedding adapters are intentionally out of scope for M6.
- Segments are not yet consumed by real ASR or speaker embedding models.
- ASR, speaker diarization, speaker embeddings, model adapters beyond
  segmentation, Raspberry Pi optimization, ExecuTorch export, and hardware
  acceleration remain intentionally out of scope for M6.
