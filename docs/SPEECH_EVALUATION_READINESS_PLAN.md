# Speech Evaluation Readiness Plan

This document plans the next evaluation-tool phase. It does **not** implement
campaign generation, metric ranking, or a Cartesian evaluation runner.

## Permanent ASR safety boundary

Only Whisper Tiny, Base, and Small are permitted. This applies to component
discovery, model bootstrap, qualification, campaign planning, resolved configs,
tests, and downloads. A Faster-Whisper backend must use one of those same three
sizes. The current Faster-Whisper component is Tiny.

## Candidate inventory

| Pipeline part | Quality candidates | Control/baseline |
|---|---|---|
| VAD | Energy, Silero, WebRTC, Sherpa-ONNX | VAD disabled |
| Segmentation | VADChunker | Full record (segmentation disabled) |
| ASR | Whisper Tiny, Whisper Base, Whisper Small, Faster-Whisper Tiny, Sherpa-ONNX, Vosk, WeNet | No-op only for contract tests |
| Anonymous diarization | pyannote Community-1, Sherpa-ONNX, Picovoice Falcon, NeMo clustering/MSDD | Diarization disabled |
| Speaker embedding | SpeechBrain ECAPA, WeSpeaker, Sherpa-ONNX 3D-Speaker, Resemblyzer | Embedding disabled |
| Known-speaker matching | Cosine threshold using a model-compatible enrollment database | Matching disabled |
| Simple speaker attribution profile | VAD chunks, per-chunk embedding and cosine scores, 2-of-3 temporal confirmation | Not an anonymous diarizer |

No-op implementations remain useful for interface and failure-isolation tests,
but they are not quality candidates.

## Compatibility rules

1. Full-record ASR uses VAD and segmentation disabled. Enabling a VAD without a
   segmenter measures VAD output but cannot change ASR input, so it must not be
   presented as a distinct end-to-end ASR candidate.
2. A VAD-conditioned ASR pipeline is `VAD -> VADChunker -> ASR`.
3. An anonymous-diarization pipeline is `diarizer turns -> VADChunker -> ASR`.
   Do not also vary a VAD in that scenario unless a future resolver defines an
   explicit intersection/union policy.
4. Cosine matching requires a real embedding backend and an enrollment database
   generated by the same model identifier and vector dimension.
5. Enrollment databases are backend-specific. One database must not be reused
   across ECAPA, WeSpeaker, Sherpa, and Resemblyzer.
6. Anonymous diarization labels (`speaker_00`, `speaker_01`, ...) are not enrolled
   identities. Enrollment matching is a separate speaker-attribution experiment.
7. pyannote qualification requires accepted model terms plus a Hugging Face
   token. Falcon requires a Picovoice AccessKey. NeMo qualification belongs on a
   supported Linux environment with its actual checkpoints and config.
8. A backend advances only after real inference, schema validation, identity
   preservation, and at least one meaningful interoperability smoke pass.

## Planned staged tests

### Stage 0 — availability and contract qualification

- Run each of the seven ASR configs on one deterministic speech file using
  full-record input.
- Run all four VADs in isolation, then as
  `VAD -> VADChunker -> reference ASR`.
- Run all four embedding backends in isolation, then as
  `embedding -> cosine matcher -> reference ASR`, using a temporary matching
  enrollment generated by that same backend.
- Run each anonymous diarizer in isolation, then as
  `diarizer -> chunker -> reference ASR`.
- Test the temporal speaker-evidence algorithm with deterministic score
  sequences and through the simple speaker-attribution profile.
- Record `qualified`, `unavailable`, or `failed`; never convert an unavailable
  component into an implicit no-op.

The repository command for this gate is:

```powershell
python "Software Validation from Datasets/Evaluation Tool/scripts/qualify_speech_components.py" --strict
```

### Stage 1 — ASR screening

Run exactly seven scenarios: each ASR candidate with full-record input, VAD,
diarization, embedding, and matching disabled. Compare WER/CER, empty output,
latency, real-time factor, memory, and failure rate. Preserve accuracy/latency
trade-offs rather than selecting a single opaque score.

### Stage 2 — VAD and segmentation screening

Use one declared reference ASR and compare five end-to-end inputs:

1. full record;
2. Energy + VADChunker;
3. Silero + VADChunker;
4. WebRTC + VADChunker;
5. Sherpa-ONNX VAD + VADChunker.

Then cross-check only the strongest one or two VAD/segmentation candidates with
all qualified ASRs. This is 7 or 14 targeted cross-checks, not every theoretical
combination.

### Stage 3 — diarization screening

With one stable ASR, compare diarization disabled, each qualified anonymous
diarizer, and the simple enrolled-speaker temporal attribution profile. Score
anonymous diarization only where compatible time/speaker references exist. Do
not claim DER/JER from a simple overlap check.

### Stage 4 — speaker embedding and matching

On disjoint enrollment/probe audio, compare:

- speaker processing disabled;
- each of four embedding backends without matching;
- each embedding backend with its own cosine-matcher enrollment database.

Evaluate extraction failures, norm/dimension, same/different-speaker similarity,
EER/FAR/FRR, identification, and unknown rejection before tuning thresholds.

### Stage 5 — targeted combinations

Retain the strongest one or two candidates per family. Generate only technically
plausible interactions: segmentation x ASR, segmentation x embedding, acoustic
condition x matching, and shortlisted diarization x ASR. Every retained
component must appear in at least one pairwise interoperability scenario.

## “One model at a time” execution policy

The evaluation runner should default to one pipeline scenario at a time per
machine (`model_job_concurrency: 1`). A scenario naturally contains several
pipeline components, but a second scenario must not load another model set in
parallel. CPU-only scoring/report generation may be separately parallelized.
Higher inference concurrency should require an explicit resource-qualification
experiment.

## Advancement gate

A component is ready for evaluation only when all of the following are recorded:

- config and relative paths resolve from a clean clone;
- package and exact model assets are present;
- the model loads without an implicit download;
- real inference completes on deterministic audio;
- output contract and source identity validate;
- the component passes its meaningful pipeline composition;
- repeated execution has no unexplained failure;
- platform, credential, and licensing requirements are explicit.

The later evaluation framework should consume qualification artifacts; it must
not infer readiness from a registered class name or import success.
